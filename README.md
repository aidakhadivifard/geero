# Dawnhalo — prototype

Daily affirmation & oracle-card app. A daily companion that delivers short,
beautifully presented "cards" — part oracle card, part encouraging message from a
grounded friend. Warm, confident, a little mystical.

> **Core promise:** "You're doing better than you think. Here's a little light for
> your next step."

This is a working prototype focused on the marketing-facing surfaces:

- **Today** — today's auto-generated daily card + one open input ("Have something on
  your mind?") that handles both questions and feelings, plus "Reminders for today".
- **Card result** — the reusable visual card (illustration + name + message + context)
  with **Save**, **Draw a different card**, **one follow-up**, and **Send a Spark**.
- **Send a Spark** — share a card via the native share sheet; the recipient opens a
  lightweight web page (`/spark`) with the card + a "Draw your own card" CTA. No app,
  no login (the card travels in the URL).
- **Saved**, **Calendar/streak**, **Settings** — present and functional, kept lighter
  this pass per scope.

Cards are generated by **Claude (`claude-opus-4-8`)** through a small server that keeps
your API key off the client.

## Run it

```bash
npm install
cp .env.example .env        # then add your ANTHROPIC_API_KEY
npm run dev                  # web on http://localhost:5173, API on :8787
```

Production-style single server (Express serves the built app + API):

```bash
npm run build
npm start                    # http://localhost:8787
```

### The API key

Real card text needs an Anthropic API key. The key is read **only by the server**
(`server/`) and is never sent to the browser.

- Put `ANTHROPIC_API_KEY=...` in `.env` (see `.env.example`), or export it in the
  environment, then restart the server.
- Without a key, `/api/card` returns a clear 503. Set `DAWNHALO_ALLOW_FALLBACK=1` to
  serve a small curated local card library instead — useful for clicking through the
  UI offline, off by default so you always know whether output is real.

Get a key at <https://console.anthropic.com/>.

## How card generation works

`server/cardGenerator.js` calls the Messages API with **structured outputs**
(`output_config.format`) so we get clean JSON every time:

```
{ cardName, message, context, theme, kind, reminders }
```

The system prompt encodes the brand voice and the product rules:

- **Validate before reframe** for feelings; **guidance framing** for questions.
- **No appearance focus**, even when the user mentions their looks.
- Short, card-first, at most one tasteful emoji.

The model also picks one of 12 illustration `theme`s by mood.

### Safety first (crisis handling)

Any input suggesting self-harm or crisis **bypasses the card flow entirely** and
returns a gentle message with real support resources (988, Samaritans, Find a
Helpline). This is enforced two ways:

1. A deterministic keyword gate in `server/safety.js` that runs **before any API
   call** — so it works even if the model or network is unavailable.
2. A re-check of the model's output as a second layer.

Conservative by design: when in doubt, it surfaces support.

## Illustrations

The 12 card illustrations are hand-built **SVGs** (`src/illustrations/`) in the dawn
palette. SVG was chosen for the prototype because:

- zero per-image cost and no extra API/key,
- crisp at any size — large card **and** small (calendar thumbnail / planned
  home-screen widget, per the spec),
- on-brand (deep-plum field + warm golden "halo").

**Swapping in DALL·E (or any raster) images later** is a one-file change: drop the
images in and map each `theme` to an `<img>`/renderer in `src/illustrations/index.jsx`.
The theme list (`THEMES` in `server/cardGenerator.js`) is the single source of truth the
AI matches against, so the rest of the app is unaffected.

Themes: `open_door, sunrise, path, mountain, moon, water, tree, bird, anchor, bridge,
star, flame`.

## Project layout

```
server/
  index.js           Express app: /api/health, /api/card, static serving in prod
  cardGenerator.js   Claude call, system prompt, structured-output schema, themes
  safety.js          crisis detection + support resources
src/
  components/         Today, Saved, Calendar, Settings, CardResult, OracleCard, …
  illustrations/      the 12 themed SVGs + theme→motif map
  store.js            local-only persistence (saved, history, streak, settings, spark codec)
  api.js              fetch wrapper
  SparkPage.jsx       recipient web view for /spark
```

## Out of scope this pass

Account system / cloud sync (storage is local-only), home-screen widget, open-ended
chat, multi-user readings, multi-language. Saved / Calendar / Settings are intentionally
lighter than Today, the card result, and Send a Spark.
